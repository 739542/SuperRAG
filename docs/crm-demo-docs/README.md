# SuperRAG CRM 演示文档说明

本目录用于课程演示，建议作为系统初始演示知识库上传到“文档知识治理中心”。这些文档覆盖客户、商机、合同、回款、发票五个 CRM 业务模块，适合展示“文档证据 -> RAG 检索 -> 结构化软件工程产物 -> 证据追踪”的完整闭环。

## 推荐上传顺序

1. `01_CRM客户管理模块说明.md`
2. `02_CRM商机管理模块说明.md`
3. `03_CRM合同管理模块说明.md`
4. `04_CRM回款管理模块说明.md`
5. `05_CRM发票管理模块说明.md`

上传时建议填写：

- 所属项目：`CRM 演示项目`
- 文档类型：按文件内容选择“需求文档”或“设计文档”
- 适用场景：勾选或填写“设计 / 交接 / 问答”
- 版本：`v1.0-demo`
- 摘要：用一句话说明该模块覆盖的业务对象、流程和规则

## 推荐演示问题

- 请为 CRM 客户、商机、合同、回款、发票模块生成详细文本用例。
- 请分析 CRM 项目的业务对象、业务规则、权限边界和异常场景。
- 请根据当前 CRM 文档生成需求-功能-用例-模块-证据追踪矩阵。
- 请总结 CRM 项目交接时接手者第一周要完成哪些待办。
- 当前 CRM 项目哪些结论证据不足，需要补充哪些文档？

## 预期展示效果

- 文档管理页可以看到每份文档的入库状态、chunk 数量、检索方式和质量检查。
- 文档详情页可以预览前几个 chunk，说明系统不是直接把整篇文档塞给模型，而是先切片后检索。
- 设计辅助页应能生成业务对象、业务规则、功能清单、文本用例、模块划分、权限分析、风险和追踪矩阵。
- 交接模式页应能生成当前进度、已完成/未完成事项、风险登记表、接手者待办清单、责任边界和信息缺口。
- 结果页中的引用证据、相关度分数、vector/lexical 分数可以用于解释 RAG 证据绑定能力。

## 注意事项

- 这些文档只是演示数据，不要把它们写死到业务逻辑中。
- 如果模型 API 暂时不可用，系统仍会使用 retrieval-fallback 基于检索片段生成结构化兜底结果。
- 如果某些结论没有文档依据，系统应把它们放入“待确认问题”或“信息缺口”，不要当成正式结论。
