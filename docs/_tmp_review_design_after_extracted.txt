0088: 2.1.2 系统概述
0089: SuperRAG 是一个面向本地部署场景的企业知识库问答与场景化输出系统。当前版本采用“第一版前端 + dify-lite 后端”的轻量联调形态：浏览器访问 8088 端口，由 dify-lite 根路由托管第一版前端页面，前端再通过同源 /api 调用后端接口完成文档导入、检索问答、引用证据展示、原文查看以及培训、交接、设计辅助等场景化输出。
0090: 系统当前不是完整 Dify 页面改造版，8088 主入口也不是 Docker 中 Dify Web 的 3000 端口。完整 Dify Docker 栈主要作为外围基础设施和可选依赖存在，可提供 Weaviate、sandbox、plugin daemon、db、redis 等服务，但当前 SuperRAG 主页面的业务链路由 dify-lite 直接支撑。

0236: 2.3.4 软件组成
0237: 2.3.4.1 软件概述
0238: 当前软件由前端静态页面、前端服务封装、dify-lite 后端服务、文本处理核心、存储层、可选向量库支持、模型服务配置和部署脚本组成。系统以轻量本地部署为主要设计取向，重点保证文档入库、检索问答和引用追溯链路可运行。
0239: 2.3.4.2 软件架构
0240: 软件架构采用“页面托管 + 同源 API + 后端服务分层 + 本地存储”的组织方式。前端不直接访问模型服务或数据库；后端集中处理文档解析、检索、模型调用和原文查看。模型服务参数由后端 .env 控制，降低前端泄露 API Key 的风险。

0312: P-05 | 设计辅助流程 | 前端提交设计问题；后端检索证据；design_pipeline 分步生成 JSON；output_validator 与 schema 做修复和归一；前端按多个 tab 渲染并执行 Mermaid 图示渲染。 | POST /api/scenes/design、design_pipeline.py、output_validator.py、design-service.js、app.js | 结构化设计结果、质量评估和 Mermaid 图示。
0313: 2.3.5.3 信息流程
0314: 信息流程遵循“前端采集输入—后端统一处理—本地存储和可选检索基础设施—模型生成—前端产品化展示”的方向。文档原文与知识片段被保存后，问答和场景输出通过 citations 保留证据链，再通过原文查看接口实现从回答回到原始文档的追溯。
0315: 2.3.5.4 流程和信息交换设计
0316: 前后端主要通过 JSON 接口交换信息。文档上传使用 multipart/form-data；场景接口返回结构化 JSON；引用原文接口通过 query 参数传递 chunkId、documentId、sourceName。设计辅助场景当前采用“后端分步生成 + schema 校验/修复 + 前端 tab 化渲染 + Mermaid 图示渲染”的组织方式，前端会根据结构化字段呈现业务分析、功能清单、用例、模块、数据与权限、追踪关系、风险、后续动作和图示结果。

0403: 2.3.9 设计辅助与 Mermaid 图示输出说明
0404: 设计辅助当前定位为“结构化设计输出 + 浏览器端图示渲染”。后端 design_pipeline 会结合检索证据分步生成业务分析、功能清单、详细文本用例、模块建议、数据对象、权限分析、异常场景、风险、待确认问题、追踪矩阵、证据覆盖、后续动作与 diagram；随后通过 output_validator 和 app/schemas 对 JSON 做修复、schema 归一和质量评估。前端 design-service.js 与 app.js 会把这些字段映射为业务分析、功能清单、详细文本用例、模块划分建议、数据与权限、需求追踪、图示输出、风险与待确认问题、后续动作建议等 tab；其中 diagram 使用 Mermaid 文本图示方案，渲染失败时保留源码查看和复制能力。
0405: 该能力适合表达流程关系、模块关系和设计草图，是设计辅助场景的重要增强探索。但当前不能描述为自动生成专业 UML 图片，也不能描述为已完整支持所有标准 UML 图或已集成 PlantUML 引擎。
