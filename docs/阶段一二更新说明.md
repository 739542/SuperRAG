# SuperRAG 阶段一、二更新说明

更新时间：2026-05-31

## 一、更新目标

本次更新主要解决 SuperRAG 从“课程演示型 RAG 页面”升级到“面向软件研发团队的知识交接与需求设计辅助系统”的核心能力问题。

重点目标包括：

- 提升设计辅助和项目交接的后端生成质量。
- 让输出结果从普通 AI 摘要升级为结构化软件工程产物。
- 增强前端对结构化字段、证据引用和质量检查的展示能力。
- 降低本地演示对 Weaviate / Docker 的强依赖，提升启动稳定性。
- 增加 CRM 演示文档，便于答辩和功能展示。

## 二、后端能力更新

### 1. 设计辅助生成增强

设计辅助已从单次大模型调用升级为拆分式生成流程。

当前 Pipeline：

```text
aucmr-design-pipeline-v1.6-split
```

设计辅助会按以下子任务生成并合并结果：

- 业务对象、业务规则、功能清单、数据对象、权限分析。
- 详细文本用例蓝图。
- 模块划分、设计风险、后续动作和图示输出。
- 需求、功能、用例、模块、证据追踪矩阵。

系统会将模型输出与检索证据候选合并，避免复杂文档下只生成少量用例或功能点。

### 2. 项目交接生成增强

项目交接已升级为可执行交接清单生成器，支持输出：

- 项目背景。
- 当前进度。
- 已完成事项。
- 未完成事项。
- 风险登记表。
- 接手者待办清单。
- 责任边界。
- 依赖文档。
- 信息缺口。
- 交接检查清单。
- 证据映射。

### 3. 结构化输出校验与容错

新增轻量 schema 与输出校验逻辑：

- `DesignOutput`
- `HandoverOutput`
- JSON 安全解析与修复。
- 结构化字段补齐。
- evidence coverage / quality assessment。

当模型返回非严格 JSON 时，系统会尝试修复并继续使用模型结果，而不是直接回退到 mock。

### 4. 本地检索模式

新增配置：

```env
DIFY_LITE_VECTOR_STORE=local
```

默认使用本地 Hash 向量 + 词法检索，不再强依赖 Weaviate。

如果后续需要使用 Weaviate，可以改为：

```env
DIFY_LITE_VECTOR_STORE=weaviate
```

并确保 Weaviate 容器已启动。

## 三、前端展示更新

### 1. 设计辅助页面

设计辅助页面已增强展示以下结构化内容：

- 业务对象识别。
- 业务规则。
- 功能清单。
- 详细文本用例。
- 模块划分建议。
- 数据对象建议。
- 权限与角色分析。
- 异常场景与设计风险。
- 待确认问题。
- 需求追踪矩阵。
- 证据覆盖率。

页面也支持展示生成来源和 Markdown 导出。

### 2. 项目交接页面

项目交接页面已增强展示：

- 项目背景与当前进度。
- 已完成事项 / 未完成事项。
- 风险登记表。
- 接手者待办清单。
- 责任边界。
- 依赖文档。
- 信息缺口。
- 交接检查清单。
- 证据映射。

### 3. 生成来源标识

前端结果区支持区分：

- 真实模型生成。
- JSON 修复生成。
- 检索兜底生成。
- Mock 回退。

## 五、验证结果

已完成本地验证：

- 后端服务可启动并监听 `http://127.0.0.1:8088`。
- `/api/config` 返回 `model_enabled=true`、`vector_store=local`。
- 检索接口可返回命中文档，且不再出现 Weaviate 502 警告。
- 设计辅助可返回 `source=openai-compatible`、`structuredSource=model-split-json`。
- 项目交接可返回真实模型结构化结果。

## 六、当前限制

- 当前默认使用本地检索模式，适合课程演示；如需生产级向量召回，可接入 Weaviate。
- 模型返回 JSON 偶尔需要后端修复，系统已支持自动修复。
- 文档治理与 RAG 可见性页面仍需第三阶段继续增强。
- 当前还未新增单文档 chunk 详情接口，第三阶段建议优先实现。
